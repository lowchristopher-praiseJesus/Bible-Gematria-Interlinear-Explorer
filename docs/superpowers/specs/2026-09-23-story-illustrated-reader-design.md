# Illustrated Story Reader Design Spec

**Date:** 2026-09-23
**Status:** Approved for planning

## Purpose

Tell a Story mode (see `docs/superpowers/specs/2026-09-23-tell-a-story-mode-design.md`
and `CLAUDE.md`'s "Tell a Story mode" section) currently delivers a
finished story as plain text: one continuous prose blob shown inline in
the docked artifact sidebar (`StoryArtifact.tsx`), with a Copy button and
nothing else. This spec adds a full-screen, page-by-page illustrated
reader — closer to a real picture book — reachable via a new icon on the
existing artifact.

End-to-end experience after this change:

1. A story finishes generating exactly as today (`ThemePicker` → "Make my
   story" / "Try again" → `story_mode._story_turn`), except the story is
   now structured as a title, a cover, and a small number of short pages
   (word count and page count both scaled to the chosen age range) rather
   than one blob.
2. The chat message's artifact pill and the docked `StoryArtifact` panel
   are unchanged in spirit, but `StoryArtifact` gains a "Read full screen"
   icon button.
3. Clicking it opens `StoryReaderOverlay`, a full-screen page-flip reader:
   a cover page (title + cover illustration), then each story page in
   turn (illustration + short text), navigated with arrow buttons,
   keyboard arrows, and a "3 / 7" page indicator — modeled on the
   full-screen picture-book readers Google's Gemini app and similar tools
   already popularized.
4. Illustrations are generated by the Gemini API's
   `gemini-3.1-flash-lite-image` model (Google AI Studio, "Nano Banana 2
   Lite"), server-side, and appear progressively — the reader is usable
   immediately on open (text always present); each page's illustration
   fades in as it finishes generating in the background, independent of
   the chat turn's latency.
5. Illustrations are cached (content-hash keyed, same pattern as
   devotional audio) so re-opening a story or reloading the page does not
   regenerate images that already exist, and are stored as small URLs in
   the browser's persisted session state, never as inline image data.

### Non-goals

- No change to theme derivation, the `StoryStarterScreen` picker, age-band
  word targets' *totals*, character-name-pool logic, or the "Try again"
  button's location — all unchanged.
- No illustration editing, regeneration of a single page's image, or
  user-supplied art direction — v1 always auto-generates every page's
  image from the story's own content.
- No offline/print export of the illustrated book.
- No changes to Deep Study, Devotional, or any other mode.

## Backend: structured page generation

### Page and word count bands

`chatbot/story_mode.py` adds a page-count band parallel to the existing
`AGE_WORD_BANDS`, so younger readers get fewer, shorter pages:

```python
AGE_WORD_BANDS = {
    "3-6": (500, 800),
    "7-8": (800, 1200),
    "9-10": (1200, 1800),
}

PAGE_COUNT_BANDS = {
    "3-6": (5, 6),
    "7-8": (7, 8),
    "9-10": (9, 10),
}
```

### Structured story completion

`generate_story` changes from parsing a `Title: ...` line plus prose into
parsing a JSON object, the same tri-state-aware pattern `derive_themes`
already uses (`_extract_json_object`). The system prompt is rewritten to
ask for:

```json
{
  "title": "string",
  "characters": "one line per named character: name — brief physical appearance, for a consistent illustration style",
  "cover_scene": "one sentence describing the cover illustration",
  "pages": [
    {"text": "one short page of story prose", "scene": "one sentence describing this page's illustration"}
  ]
}
```

- `characters` is a single string (not structured further) — it exists
  purely to be appended to every page's image prompt for visual
  consistency across independently-generated images (Gemini's image
  model has no memory between calls, the same reason
  `CHARACTER_NAME_POOL` exists for names).
- The prompt states the target page count range from `PAGE_COUNT_BANDS`
  and total word range from `AGE_WORD_BANDS`, and asks each page to be
  roughly even in length.
- `word_count` becomes `sum(len(p["text"].split()) for p in pages)`. The
  existing retry-once-if-far-outside-band logic is unchanged in spirit,
  just operating on the summed count and re-requesting the full
  structured JSON.
- Malformed/unparseable JSON is treated the same way a failed
  `simple_completion` already is elsewhere in this module: an honest
  "I couldn't write the story just now" error from `_story_turn`, not a
  silent fallback to some degraded shape.
- `_split_title`/`_TITLE_LINE_RE` and the old free-prose system prompt are
  deleted; `_story_prompt` gains `page_low`/`page_high` params from
  `PAGE_COUNT_BANDS`.

### Illustration generation module

New `chatbot/story_illustrations.py`, structurally parallel to
`chatbot/devotional_audio.py`:

```python
import os
from pathlib import Path
from google import genai
from google.genai import types

IMAGE_MODEL = os.environ.get("STORY_IMAGE_MODEL", "gemini-3.1-flash-lite-image")
IMAGE_ASPECT_RATIO = "4:3"
STORY_IMAGE_CACHE_DIR = Path(os.environ.get("STORY_IMAGE_CACHE_DIR", "STORY_IMAGE_CACHE"))
STORY_IMAGE_CACHE_DIR.mkdir(parents=True, exist_ok=True)

STYLE_PREFIX = (
    "Children's storybook illustration, soft warm watercolor style, "
    "gentle colors, no text or words anywhere in the image. "
)

class StoryIllustrationError(Exception):
    ...

def cache_key(prompt: str) -> str:
    # sha256(prompt), same pattern as devotional_audio.cache_key(text)
    ...

def build_prompt(scene: str, characters: str) -> str:
    return f"{STYLE_PREFIX}{scene} {characters}".strip()

def synthesize_illustration(prompt: str) -> bytes:
    """One image, PNG bytes. Raises StoryIllustrationError on any
    failure (network, rate limit, empty response) — callers must treat
    this as expected and fail that one page open, never the whole
    request."""
    client = genai.Client()  # GEMINI_API_KEY from env
    response = client.models.generate_content(
        model=IMAGE_MODEL,
        contents=prompt,
        config=types.GenerateContentConfig(
            response_modalities=["IMAGE"],
            image_config=types.ImageConfig(aspect_ratio=IMAGE_ASPECT_RATIO),
        ),
    )
    for part in response.candidates[0].content.parts:
        if part.inline_data:
            return part.inline_data.data
    raise StoryIllustrationError("No image returned")
```

`cache_key`/`build_prompt` are pure and unit-testable without network
access; `synthesize_illustration` is the one network-touching function,
mocked in tests the same way `simple_completion` is mocked elsewhere.

Mounted in `chatbot/__init__.py` alongside the existing audio mount:

```python
from chatbot.story_illustrations import STORY_IMAGE_CACHE_DIR
app.mount("/story-images", StaticFiles(directory=str(STORY_IMAGE_CACHE_DIR)), name="story-images")
```

### Delivery endpoint

`_story_turn` (`chatbot/story_mode.py`) returns the artifact immediately
once the structured story is generated — no waiting on any illustration.
The artifact's `params` gain a `pages` array and a `cover` object, each
image URL starting `null`:

```python
"artifacts": [{
    "type": "story",
    "label": "Read the story ▸",
    "params": {
        "title": story["title"],
        "themes": theme_labels,
        "age_range": age_range,
        "word_count": story["word_count"],
        "characters": story["characters"],
        "cover": {"scene": story["cover_scene"], "image_url": None},
        "pages": [
            {"text": p["text"], "scene": p["scene"], "image_url": None}
            for p in story["pages"]
        ],
    },
}],
```

A new, separate, non-chat endpoint generates the images:

```python
class StoryIllustrationsRequest(BaseModel):
    characters: str
    cover_scene: str
    page_scenes: List[str]

class StoryIllustrationItem(BaseModel):
    index: int  # -1 for cover, 0..N-1 for pages
    image_url: Optional[str] = None
    error: Optional[str] = None

@router.post("/story/illustrations")
async def post_story_illustrations(request: StoryIllustrationsRequest) -> StreamingResponse:
    """Newline-delimited JSON, one StoryIllustrationItem per line, as
    each image finishes. Bounded concurrency (4 at a time) against
    Gemini API rate limits. Never raises for a single image's failure —
    emits {"index": i, "error": "..."} for that line instead, so one
    failed page never blocks or breaks the rest."""
```

This keeps the existing chat `/chat` and streaming (`/chat/stream`)
contracts completely untouched — Tell a Story still has no `mode ==
"story"` branch in `chatbot/api.py`, and illustration generation is
invisible to `router.build_mode_primer`. The frontend calls this new
endpoint itself, the same way `postDevotionalAudio` already calls
`/devotional/audio` as its own separate request outside the chat flow.

### Failure handling

- Structured story JSON fails to parse after the retry → existing
  "I couldn't write the story just now" error path, unchanged.
- A single page's or the cover's image generation fails (network error,
  rate limit, empty response) → that one `StoryIllustrationItem` carries
  `error` instead of `image_url`; the reader shows that page as
  text-only. This mirrors `devotional_of_day`'s fail-open convention
  (CLAUDE.md) and `ollama_client.simple_completion`'s never-raise
  contract — a missing illustration is a degraded page, not a broken
  story.
- If the Gemini image API key is unset, `synthesize_illustration` raises
  immediately for every page; the endpoint still returns 200 with every
  item carrying `error` (not a 502) so the reader degrades to
  text-only pages rather than the whole illustration fetch failing
  client-side.

## Frontend

### Types (`frontend/src/types/session.ts`)

```ts
export interface StoryPage {
  text: string
  scene: string
  image_url: string | null
}

export interface StoryArtifactParams {
  title: string
  themes: string[]
  age_range: string
  word_count: number
  characters: string
  cover: { scene: string; image_url: string | null }
  pages: StoryPage[]
}
```

### `StoryArtifact.tsx`

- Adds a `BookOpen` icon button ("Read full screen") in the header row
  next to the existing Copy button, opening `StoryReaderOverlay` via a
  local `open` boolean state — identical wiring to how
  `DevotionalArtifact` opens `DevotionalListenOverlay` with its
  `Headphones` button.
- Copy button now joins `pages.map(p => p.text).join('\n\n')` instead of
  the old single `text` field.
- Inline body preview: first page's text (or a short "N-page story"
  summary) instead of the full story, since the full read is now the
  full-screen reader's job — exact wording decided during
  implementation, not load-bearing for this spec.

### `StoryReaderOverlay.tsx` (new, `components/artifacts/`)

Structurally modeled on `DevotionalListenOverlay.tsx`: Radix
`Dialog.Root`/`Portal`/`Overlay`/`Content` at `fixed inset-0 z-50`, props
`{ artifact: StoryArtifactParams, open: boolean, onClose: () => void }`.

- Local page index state, `0` = cover, `1..pages.length` = story pages.
- On mount (when `open` becomes true) and only once per artifact
  instance: if any image URL is still `null`, POST to
  `/story/illustrations` with `characters`, `cover.scene`, and each
  page's `scene`; read the streamed newline-delimited response and, for
  each line, update that page's `image_url` (or leave it null on
  `error`) via a callback prop, e.g. `onIllustrationsResolved: (updates)
  => void`, wired in `ChatPane`/wherever the artifact's owning message
  lives so the resolved URLs are written back into that message's
  `artifacts[].params` in `useSessionsStore` — persisted through Zustand
  `persist` like the rest of session state, so a reload shows
  already-fetched images without re-generating them.
- A page whose `image_url` is still `null` (loading or failed) shows a
  soft placeholder (shimmer while an in-flight request for it exists,
  plain background if it errored) — reading is never blocked on images.
- Navigation: left/right arrow icon buttons, `ArrowLeft`/`ArrowRight`
  keydown handling while open, and a small "current / total" indicator
  (`"3 / 7"`), styled after the Gemini storybook reader referenced
  earlier in this conversation.
- `Dialog.Close`-wrapped "Done"/exit button, same as
  `DevotionalListenOverlay`.
- New `.story-reader-bg` class in `index.css`, following
  `.devotional-listen-bg`'s pattern (themed gradient + dark scrim for
  contrast) rather than the plain `VerseFullscreen` background, since
  this is meant to feel like an immersive book, not a document viewer.

## Config

`requirements.txt`: add `google-genai>=?.?.?` and `pillow>=?.?.?` (exact
pinned versions decided at implementation time against what's current).

`.env.example`: add, near the other provider keys —

```
# ─── Tell a Story illustrations (Gemini API image generation) ─────────────
# Read by chatbot/story_illustrations.py. A standard Google AI Studio API
# key (ai.google.dev) — no GCP service account needed, unlike the TTS key
# above. Free-tier keys are rate-limited; a failed/rate-limited image
# request degrades that one page to text-only rather than failing the
# story. Put the real value only in .env, never in .env.example.
GEMINI_API_KEY=
# Override only if Google renames/deprecates the model id below.
STORY_IMAGE_MODEL=gemini-3.1-flash-lite-image
```

`STORY_IMAGE_CACHE_DIR` follows `AUDIO_CACHE_DIR`'s pattern exactly
(env-overridable path, default relative dir, created at import time) and
needs the same kind of Docker volume mount `DEPLOYMENT.md` already
documents for `AUDIO_CACHE_DIR` — that doc gets a matching entry.

## Testing

- `tests/chatbot/test_story_mode.py`: update the existing structured-JSON
  tests for `generate_story` to assert on `pages`/`title`/`characters`/
  `cover_scene`, page-count bounds per `PAGE_COUNT_BANDS`, and that the
  word-count retry sums across pages. Existing tests for the abstract-
  ending prompt rule and character-name-pool assignment adapt to the new
  prompt shape but keep the same assertions in spirit.
- New `tests/chatbot/test_story_illustrations.py`: `cache_key` and
  `build_prompt` are pure-function tests (no network). A mocked
  `synthesize_illustration` (monkeypatched, mirroring how
  `ollama_client.simple_completion` is mocked elsewhere) verifies the
  `/story/illustrations` endpoint's per-item success/error behavior,
  concurrency cap, and that one page's failure doesn't affect the others'
  results.
- Frontend: `StoryArtifact.test.tsx` updates for the new button and the
  changed Copy behavior; new `StoryReaderOverlay.test.tsx` covers page
  navigation, keyboard arrows, the placeholder-while-loading state, and
  that a failed page's `error` leaves it in the text-only state rather
  than throwing.

## Open questions / risks (flagged, not blocking)

- **Model id verification:** `gemini-3.1-flash-lite-image` is taken on
  the user's word (this session's knowledge cutoff is Jan 2026, and
  Google ships image models quickly) — the `STORY_IMAGE_MODEL` env
  override exists specifically so this is a one-line fix if the id has
  moved by implementation time.
- **Cost/quota:** every "Try again" regenerates up to
  `PAGE_COUNT_BANDS`-many-plus-one images. No client- or server-side
  throttle on repeated "Try again" clicks is proposed here beyond
  whatever Gemini's own rate limiting enforces — acceptable for v1 given
  YAGNI, worth revisiting if usage/cost data says otherwise.
- **`google-genai` dependency footprint:** first new Python dependency
  this repo has pulled in specifically for image generation; pin exact
  versions at implementation time and confirm it doesn't conflict with
  existing `httpx`/`pydantic` version constraints already pinned in
  `requirements.txt`.
